# ADR 0001: Workstation vs Workplace

## Контекст
В системе есть две похожие сущности рабочих мест:
- `core.Workstation` — используется для контроля доступа и хранения списка разрешенных пользователей.
- `polls.Workplace` — используется как аудитория для опросов и содержит IP/метку/подразделение.

Дублирование сущностей повышает риск расхождений, особенно по IP и принадлежности рабочих мест.

## Варианты
1. Оставить всё как есть и синхронизировать вручную (риск расхождений, скрытые ошибки).
2. Ввести явную связь между моделями и назначить источник истины (минимизирует риск, сохраняет текущие модели).
3. Полностью объединить модели в одну (требует миграций и может затронуть бизнес-логику).

## Решение (минимальный риск)
Выбрать вариант 2: добавить явную связь `polls.Workplace -> core.Workstation` и определить `core.Workstation` как источник истины для IP/идентификаторов. На уровне бизнес-логики в `polls` использовать связанную сущность при наличии.

## Последствия
- Появляется единая точка истины для IP и метаданных рабочих мест.
- Снижается риск расхождений между аудиториями опросов и контрольными списками доступа.
- Потребуются последующие изменения моделей/миграций, но без мгновенной ломки текущих сценариев.
